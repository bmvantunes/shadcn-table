# Project edit-review Rows through a consumer seam

Editable Client Tables place a narrow `projectEditRow({ row, patch })` interface at the edit-review Row projection seam so consumers can construct an authentic `TRow` for row-aware Yours presentation. BrunoTable supplies the current source Row and an exact sparse patch limited to potentially editable fields; the consumer adapter returns a presentation-only Row and does not alter source authority, Row Versions, save evidence, or canonical values. An exact finite Column tuple makes this interface mandatory when a potentially editable Field Column declares a `valueFormatter`, callback `cellClassName`, or `cellRenderer`; widened Columns retain an optional TypeScript surface and Client construction rejects missing configuration when normalized capabilities prove that the seam is required.

## Considered options

BrunoTable does not clone, proxy, or temporarily mutate arbitrary Rows. Clones cannot preserve private fields, WeakMap identity, closure-backed state, or every accessor invariant; proxies change method receivers and similarly break identity-backed behavior. Binding callbacks or methods to the source Row would expose Server sibling values as Yours, and inspecting callable source text is heuristic across closures, transforms, and minification. Falling back to the source Row is therefore false evidence, while a broad controller or per-renderer replacement would leak table internals and duplicate one projection policy across presentation callbacks.

## Consequences

Plain-record consumers may explicitly merge the patch, while class or prototyped models can delegate to a domain constructor or `withEditPatch` method that preserves their invariants. Value-only edit review remains available without the seam. BrunoTable may reuse a cached projection for an identical source Row reference, opaque Row Version, projector configuration, and exact patch. The adapter may also return the same memoized immutable Row for those identical inputs, including across review close and reopen. Changed source or patch evidence requires the adapter to return a fresh immutable Row replacement.

Missing required configuration is an explicit construction error. Before a Row has published one valid projection, a projector throw, null or non-object result, source-Row result for a non-empty patch, Row Identity read failure, changed Row Identity, or reused historical result is also an explicit configuration error. Once a valid projection has been published for that Row, any of those failure classes on changed inputs instead drops the projection and marks row-aware Yours `Unavailable`. Exact Mine, Base, and Server evidence remains intact and the admitted review workflow continues coherently rather than retaining possibly mutated evidence or substituting the Server Row. Missing or unreadable current source evidence also remains explicitly unavailable. These failure modes preserve truthful review publication without fabricating Yours.
