# Separate row concurrency versions from query versions

Editable Client Tables require a pure `getRowVersion(row)` function whose inferred return type becomes the exact Row Version throughout drafts, expected versions, conflicts, and Accepted Overlays. Read-only Client Tables and Server Tables reject that prop. A Viewport Source's top-level Query Version is never used as a row's expected version, and the effect-view-server runtime `patch` operation is not a Save Adapter because it currently has no compare-and-set argument. `onSaveEdits` must cross an application write or RPC seam that atomically checks the Row Version; it resolves or rejects with no row payload, while canonical values and the next version arrive through the live Client Source as refined by ADR-0022.
