# Separate row concurrency versions from query versions

Editable Client Tables require a pure `getRowVersion(row)` function whose inferred return type becomes the exact Row Version throughout drafts, expected versions, conflicts, and save results. Read-only Client Tables and Server Tables reject that prop. A Viewport Source's top-level Query Version is never used as a row's expected version, and the effect-view-server runtime `patch` operation is not a save Adapter because it currently has no compare-and-set argument. `onSaveEdits` must cross an application write or RPC seam that atomically checks the Row Version and returns canonical values plus the next version.
