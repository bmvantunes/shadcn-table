# Use one scroll owner and exact Cell reveal

The shared renderer owns one native two-axis scroll element as the sole authority for offsets, viewport dimensions, virtual windows, pinned insets, measurement, and hit testing. A visual Scroll Area may decorate or expose that same viewport, but it may not introduce a second scroll owner. The first live Client slice uses a BrunoTable-owned custom viewport runtime to window rows and centre columns; this private seam may later adopt TanStack Virtual without changing the renderer or public API. Start- and end-pinned columns remain continuously mounted in separate sticky regions while TanStack Table supplies their single Logical Column Order. Any layout with pinned columns is the exception before its viewport is measured. After measurement, suspension continues when active pinned widths would leave less than 80 CSS pixels for an existing centre region, or when a centreless pinned layout is wider than its viewport. While suspended, pinned insets become zero and one bounded horizontal window virtualizes start → centre → end. Measuring or widening the viewport until the active pinned layout fits restores the sticky regions automatically.

Keyboard navigation never delegates destination reveal to a nearest-index `scrollToIndex` heuristic. For fixed geometry, the renderer computes the destination cell's logical bounds, subtracts the active sticky header/start/end insets, and applies only the minimum clamped `scrollTop` and `scrollLeft` deltas. While pinning is suspended, the start/end insets are zero and formerly pinned destinations reveal within the continuous horizontal window. Initial Active Cell installation is one-shot state initialization and must not replay after a virtual-window render.
